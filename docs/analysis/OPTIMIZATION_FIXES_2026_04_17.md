## P0 修复（必须）

### P0-1: 像素光效 speed 下标越界

**文件**: `modules/light_effect_pixel/light_effect_pixel.c`  
**问题**: speed 作为数组下标使用，但多个分支仅做上限检查（>2），不做下限检查。  
**风险**: speed=0 或负值导致越界访问，可能造成闪烁/崩溃。

**修复方案**:
- 于所有 effect 初始化分支（pulinsh/swing/swing_ii/rotate）加入统一的下限保护。
- 改为: `if(speed < 1) speed = 1; else if(speed > 3) speed = 3;`
- 确保 speed 最终值总是 ∈ [1, 3]。

**验证**:
```bash
# 输入 speed=0, 255 等边界值，检查数组访问是否越界
# 压测 30 分钟连续切换 effect 和 speed，观察无崩溃
```

**改动统计**:
- lines 273-276 (pulinsh_init)
- lines 374-377 (swing_init)
- lines 502-505 (swing_ii_init)
- lines 610-613 (rotate_init)

### P0-2: RGB→PWM 整数截断

**文件**: `components/dev_lamp/dev_lamp.c`  
**问题**: 计算 `r / 100 * PWM_MAX` 时，r < 100 会先被整数除法截断为 0。  
**风险**: 低亮度（<1%）RGB 无法正确显示，用户感知为"颜色不准"。

**修复方案**:
- 改为先乘后除: `r * PWM_MAX / 100`
- 保证浮点精度，避免中间截断。

**验证**:
```bash
# 设置 r=1~99，检查 PWM 输出值连续分布
# RGB 梯度测试 0-100%，检查无明显断层
```

**改动统计**:
- line 472: pwm 数组初始化公式

## P1 修复（近期完成）

### P1-1: FFT 热路径性能优化

**文件**: `main/app/app_power.c`  
**优化点**:

1. **用 ldexpf 替代 pow**
   - 位置: line 357
   - 改动: `pow(2, fft_exponent)` → `ldexpf(1.0f, fft_exponent)`
   - 收益: 30-50% CPU 时间节省（ldexpf 是专用整数指数函数）

2. **降频状态写入**
   - 位置: line 428-436
   - 改动: 从每 10ms 写一次改为每 50ms 写一次（5 次周期）
   - 收益: 消除高频 NVS/SPI 写入瓶颈，减轻总线竞争

**验证**:
```bash
# 记录优化前后的 Power 任务执行耗时
# 在网络+灯效并发下，观察帧率稳定性（FPS variance）
# 目标: 任务耗时下降 ≥20%
```

**改动统计**:
- line 357: ldexpf 替换（1 行）
- line 428-436: 写入降频（8 行）
